- **#10 design:** `convex/attemptInteraction/` adds `send`/`retry` mutations; recorded messages and open exchange state are read through the existing `ownAttempt`. Each Learner message appends a `learner_message` event and an `exchangeRequests` row keyed by a browser `clientRequestId`. A scheduled internal action calls Gemini (key from the Convex env only). It uses `gemini-3.5-flash` with `gemini-3.1-flash-lite` as the fallback: a 503 is retried once, then a lasting 503, a 429, a 404, or a 12 s timeout moves to the fallback. `gemini-2.5-flash` returns 404 for new keys, and the user's free tier is too small for `gemini-3.8-flash`. The action sends the Learner Brief, pinned `clinicalTruth.initialState`, and prior messages. `progression` is withheld until #11. Policy: one open exchange per Attempt. A different request is refused while one is pending, and a new message supersedes (abandons) a failed one. Resending or retrying the same request never records a second Learner message. Only the current `generation` may commit, and only while the Attempt is Active. A 60 s deadline turns an interrupted generation into a retryable failure. Start again abandons open exchanges, and late replies append nothing.

- **Limitations:** Inherited from #9: Start has no request-level retry idempotency, and reload does not recheck availability. Before its 60 s deadline, a pending reply shows "responding" without Retry, so a stuck reply takes up to 60 s to become retryable. A Learner message whose send never reached the server is lost on reload (Convex retries it while the page stays open). Grounding is prompt-based. Replies are not screened for invented vitals or findings; they are only stored as timeline evidence, never as Clinical Truth.
